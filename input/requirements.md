# 需求入口

## REQ-001：Purity 节点世界地图与节点提交

- 首页原 Ocean Mining Hashrate 和 Bitcoin Knots Nodes 两张卡片替换为一张整行 Purity 世界地图。
- 从 `https://seed.bitcoinpurity.org/api/listnodes` 获取数据，仅展示 `status=purity` 的 IP＋端口记录。
- 区分公开 P2P（`p2p_reachable=1`）与非公开／未确认可达（`0/null`）；明确探测失败、尚未探测和单个 Seeder 观察点的语义。
- 通过本地 GeoLite2-City 定位 IP；不能定位的节点保留在统计中。
- 任何访客可提交公网 IPv4／IPv6 和端口，通过后端调用 Seeder `/api/addnode`，默认端口 8333。
- 凭证仅由后端环境变量提供。按可信来源限流为每分钟一次，每后端进程至多两个并发验证。
- 列表缓存和页面刷新周期 60 秒；查询超时 15 秒，添加验证超时 60 秒，不自动重试添加。
- 地图支持两类图例、统计、缩放、拖动和节点详情；添加结果区分确认、其他链、未完成和重复节点。
- 补充需求、规格、架构、接口、迁移和任务文档；测试先行，完成编译及相关回归测试。部署单独执行。

## REQ-002：地图显示开关

- 添加前端布尔配置 `PURITY_NODES_MAP_ENABLED`，默认 `true`，控制主网首页整张地图卡片（含添加节点入口）的显示。
- 设置为 `false` 时不创建地图组件，不请求节点列表或启动其刷新计时器；保持原 Ocean／Knots 卡片移除后的布局。
- 普通前端配置文件及 Docker 前端环境变量均支持此开关。该开关只控制页面展示，后端 API 契约不变。

## REQ-003：后端冷启动增量同步诊断与修复

- 同一 BitcoinApi 实例的冷启动 verbose mempool 元数据初始化共享一个在途 Promise；成功保留缓存，失败清理并允许后续重试，手续费计算不变。
- 每轮记录 Core／本地缓存／缺失／过期交易数量和同步状态；记录批次开始、成功／失败数量及耗时。初始同步用 info，常规进度用 debug，慢操作用 warn。
- 逐笔抓取保持并发 8，统计成功、失败、慢请求、超时和最大／整体耗时；RPC 慢请求阈值 5 秒。失败仍按原规则过滤，在后续周期重新抓取。
- watchdog 保持 120 秒，在所有退出路径清理，阶段对应实际等待的抓取、候选集、回调及 Redis 操作。
- 保留磁盘缓存、RBF、Redis、Electrum、Esplora 和 Purity 行为；不改共识、数据库、公开 API、RPC 认证／超时或并发。只评估连接复用，不在本任务修改传输层。
- 测试先行，执行编译、相关测试和 lint；提供诊断示例及 Ubuntu 部署／回滚步骤。未经批准不推送、部署或重启生产服务。

## REQ-004：节点标记层级与后端 Archive / Prune 类型

- 标记重叠时，可访问节点（`p2p_reachable=1`）始终绘制在非公开／未确认节点上方；保留同坐标节点展开和分类筛选。
- 根据 Seeder 的 `services` 区分 Archive 与 Prune：含 `NODE_NETWORK`（bit 0）为 Archive；不含该位但含 `NODE_NETWORK_LIMITED`（bit 10）为 Prune。两位同时存在时为 Archive。
- 后端缺少有效服务标志或两个标志均未声明时返回类型未知，不依据高度、客户端字符串或可访问性猜测类型。
- 前端取消 Archive / Prune 的颜色、图例及类型详情，仅以绿色实心圆表示可访问，以橙色空心菱形表示非公开／未确认；不使用后端的 `node_type` 字段。
- 后端类型识别及 `node_type` 响应契约维持不变。
- 仅修改本项目，通过现有 Seeder 库存读取类型信息；不修改 Seeder，不包含部署。

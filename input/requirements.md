# 需求入口

## REQ-001：Purity 节点世界地图与节点提交

- 首页原 Ocean Mining Hashrate 和 Bitcoin Knots Nodes 两张卡片替换为一张整行 Purity 世界地图。
- 从 `https://seed.bitcoinpurity.org/api/listnodes` 获取数据，仅展示 `status=purity` 的 IP＋端口记录。
- 区分公开 P2P（`p2p_reachable=1`）与非公开／未确认可达（`0/null`）；明确探测失败、尚未探测和单个 Seeder 观察点的语义。
- 通过本地 GeoLite2-City 定位 IP；不能定位的节点保留在统计中。
- 任何访客可提交公网 IPv4／IPv6 和端口，通过后端调用 Seeder `/api/addnode`，默认端口 8333。
- 凭证仅由后端环境变量提供。按可信来源限流为每分钟一次，每后端进程至多两个并发验证。
- 列表缓存和页面刷新周期 60 秒；查询超时 15 秒，添加验证超时 60 秒，不自动重试添加。
- 地图支持两类图例、统计、缩放、拖动和节点详情；添加结果区分确认、其他链、未完成和重复节点。
- 补充需求、规格、架构、接口、迁移和任务文档；测试先行，完成编译及相关回归测试。部署单独执行。

## REQ-002：地图显示开关

- 添加前端布尔配置 `PURITY_NODES_MAP_ENABLED`，默认 `true`，控制主网首页整张地图卡片（含添加节点入口）的显示。
- 设置为 `false` 时不创建地图组件，不请求节点列表或启动其刷新计时器；保持原 Ocean／Knots 卡片移除后的布局。
- 普通前端配置文件及 Docker 前端环境变量均支持此开关。该开关只控制页面展示，后端 API 契约不变。
